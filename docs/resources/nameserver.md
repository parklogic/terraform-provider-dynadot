# dynadot_nameserver (Resource)

Registers a child nameserver with Dynadot. The parent domain must meet Dynadot's registration requirements. Changing the hostname replaces the registration. Creation registers one sorted address, then sets the complete IP set; failures after registration retain the hostname in state. Reads and unchanged applies never call `set_ip`.

## Example Usage

```terraform
resource "dynadot_nameserver" "primary" {
  name         = "ns1.example.com"
  ip_addresses = ["192.0.2.10", "2001:db8::10"]
}
```

## Import

Import by hostname; no numeric ID is required.

```shell
terraform import dynadot_nameserver.primary ns1.example.com
```

## Recovery and deletion

If registration returns an ambiguous transport error, check Dynadot before retrying and import any registration that succeeded. Registration is not blindly retried after ambiguous failures. An in-use registration cannot be deleted; Terraform retains its state and reports an error until its dependencies are removed. Confirmed absence succeeds on deletion and removes the object during refresh.
